## This trial's question (new, falsifiable, CPU-only)

E1 left two live causes for F1: **(A)** verify-row context misalignment (mask/positions/BFS
order vs flat `target_predict` indexing) and **(B)** post-commit KV/bonus misalignment
(accepted rows like [0,2,4] with identity retrieve_index requiring compaction). The
`accept_lens == 1` discriminator was proposed but never executed (no instance had accept_len 1).

Before another mask/overlap model, this trial fixes the methodological defect the analyzer
identified: **source conventions first, independent goldens second, model third**. Concretely:

1. Extract the *real* accept-path expressions/functions from the pinned tree via AST (anchored;
   fail loudly if source moves): `eagle_utils.py` target_predict construction, `ngram_worker.py`
   accept/commit loop, `spec_utils.py` KV move, and the tree/parent/retrieve-index metadata
   construction for NGRAM.
2. Fix the convention stated by the analyzer: `mask[r, j] = 1` iff `j` is an ancestor of `r`
   **or** `j == r` (diagonal included); the root row must not see future children.
3. Build **independent golden fixtures** (hand-written expected values, not produced by the
   helper under test) for: (a) a two-node chain mask `[[1,0],[1,1]]`, (b) identity
   retrieve_index with non-contiguous accepted rows [0,2,4] requiring compaction, (c) the
   accept-length/`target_predict` index arithmetic for a small BFS tree.
4. Run a bounded replay that consumes **unpacked** outputs (not raw packed words) and asks one
   new question: can the pinned accept-path index arithmetic, under a *correct* mask and
   *correct* KV compaction, ever commit a token whose verified-context top-1 differs from the
   committed token? If yes with concrete fixture -> candidate A/B mechanism narrowed. If no ->
   explicit negative: that mechanism is excluded for the modeled conventions, with the
   unmodeled real-kernel/page/overlap parts left UNKNOWN.
